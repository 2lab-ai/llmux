## Attack surface (both personas draw from this, each with their own lens)

1. Correctness — logic, boundaries/off-by-one, unit mismatches, concurrency/cancellation, error paths that swallow failures.
2. Behavioral compatibility — API/CLI/config-schema changes: are serde defaults additive, do old configs/clients keep working, does anything change meaning silently.
3. Operator impact — deploy/rollback safety, observability (will we SEE it misbehave), failure blast radius, what could embarrass us in production.
4. Tests — do the included tests actually pin the claimed contract (or only a proxy of it), which claimed behavior is untested, would the tests have caught the bug being fixed.
5. Docs-vs-code drift — doc comments, README, and commit message claims that the diff does not actually implement.
